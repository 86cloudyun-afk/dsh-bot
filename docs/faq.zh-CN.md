# 常见问题

## GitHub 页面或下载链接返回 404

本仓库与发布资产均为私有。登录有权限的 GitHub 账号，再打开[这一版的下载页](https://github.com/86cloudyun-afk/dsh-bot/releases/tag/v0.1.0-private.1)。其他工具直接读取链接也需要对应权限；可以下载后把实际文件作为附件交给自己的工具。

## 应该下载哪一个压缩包？

下载 Assets 中的 `dsh-bot-v1-private-delivery-20261008-r2.tar.gz` 及同名 `.sha256`。它是完整交付包，内部包含 `final-1f111d7-m3-thin.tar.gz` 安装薄包。自动生成的 “Source code” 文件用于查看冻结源码。具体步骤见[下载说明](github-download.zh-CN.md)。

## 支持什么系统和 Node？

恰好 Node `24.19.0`，Linux x64 或 macOS arm64。Windows、macOS Intel 及其他 Node 版本未在本版支持范围。

## 安装需要密钥或以前的 DSH 环境吗？

安装不需要旧 DSH、旧 Home 或模型密钥。需要正常公共 npm 和访问公共 npm registry 的网络；安装器使用固定 lock、严格 TLS 和新缓存，跳过生命周期脚本。

## GUI 能打开，为什么不能发送模型任务？

默认模型请求关闭。执行实际任务时，在 CLI 的启动环境中提供 `DEEPSEEK_API_KEY`，并显式追加 `--enable-model-requests`，同时确认原会话能力与历史。按[当前指南](installation.zh-CN.md)操作。安装器不会写入或自动开启密钥。

## UNKNOWN 是任务失败吗？可以重新发一遍吗？

UNKNOWN 表示原操作、原结束状态或最终用量仍未完整确认。查询原回执，保留原身份和槽位；不自动重试，不重放输入，不换 ID 绕过。停止被接受也需要核对原生结束状态。重启不会自动重发 UNKNOWN。

## 工作结束了，主对话怎么没有收到结果？

工作结束状态和结果送达分别核对。回送上限为 4096 UTF-8 字节，中文字符通常占三个字节。先在原工作对话查看回复，再提交新的较小任务；建议每次不超过 3400 UTF-8 字节。

## 能同时运行 15 个工作吗？

账本上限是每 Bot 共用 15 槽，包含父工作、一级子工作及 UNKNOWN，主对话不占槽。此边界有原生 SDK 和 GUI 受控证据；本轮没有 15 个真实模型并发压力测试。父工作可创建一层子工作，子工作不能再次派发。

## 安装下载失败或超时，如何处理？

核对网络、代理和证书，保留失败目录与输出。修复后选择新的、尚不存在的输出目录。出现 `SDK_INSTALL_STOP_UNKNOWN` 时，先核对原 npm 子进程和进程组的停止结果，避免仅凭复用 PID 操作另一个进程。详细处理见安装指南。

## 如何重启、归档或恢复？

使用同一安装目录、`DSH_HOME` 和 `dsh-bot-gui` profile；原 CLI 和原进程组停止后再启动。归档与恢复使用原 Bot、主对话与工作身份。响应丢失或 UNKNOWN 时查询该操作的原回执。

## 这是正式公开 v1 吗？

这是已交付第一版的**私有 GitHub 预发布**。Bot 与 Host 修改的公开分发权利及 node-addon 的通知适用范围尚未确认，正式公开 v1 为 NOT_CLEARED。技术通过、仓库存在和预发布标签不等于新增公开分发许可。见[发布说明](releases/private-v1.zh-CN.md)。

## 为什么默认 main 的 CI 仍是红色？

main 保留原 `13d1fb15` 产品代码，只同步中文文档和上传工作流；PR #1 保持草稿未合并。两平台离线 CI 中的 4 项失败与原基线相同。本版安装包和标签绑定通过六组 CI 的 `1f111d7`，安装使用发布页的固定完整包，开发使用该标签。具体范围见[开发说明](development.zh-CN.md)。
