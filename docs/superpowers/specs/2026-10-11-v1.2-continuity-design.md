# v1.2 聊天接续、资料检索与恢复可靠性

状态：按用户持续自主升级授权实施；交付以独立复审、实际安装升级验收和正式 Release 为准。

## 目标与边界

让已有 Bot 更容易继续日常聊天，使知识和协作结果遵守持续可撤销的来源权限，并修复操作保存、停止状态和迟到提醒的已复现遗漏。沿用既有模块；不增加主导航、外部服务或新的权限配置。

- 直接安装到未修改的官方 DSH `0.2.0-rc.2`，Node `^22.19.0 || >=24`，Linux／macOS。
- Bot 身份、长期记忆、原生会话、任务、操作 ID 和回执保留；schema 2／协议 2 不变。
- 当前会话挂载的原生工具默认可用，沿用 DSH 审批；跨 Bot 默认只读，持续授权可撤销。
- 15 个工作槽及一级子工作、UNKNOWN 不自动重放、真实结算后释放资源的边界不变。
- 使用受控提供者与隔离官方 profile 验证；不访问用户现有 Host，不发起外部真实模型请求。

## 1. 已有聊天入口

Bot 卡片保留创建新联络会话的入口，增加“继续聊天”。列表只包含所选稳定 botId 的 ready、未归档 contact 会话，显示保存的名称与原 sessionId 以区分重名。用户选择后打开原生原会话，不创建会话、不发送消息、不启动模型。没有会话时给出明确空状态并保留新建入口。

使用完整的已授权 snapshot 绑定，不按名称匹配 Bot，不凭随机 ID 或缺失时间猜测最近会话。选择器显示期间若快照发生归档、删除、换 Bot 或会话状态变化，旧对象不能继续被打开。切换页签、关闭选择器或选择另一 Bot 时立即取消旧打开意图，不等待组件清理。插件禁用后读响应不得更新已卸载页面。

## 2. 浏览器原始操作与刷新

首次发送修改和用原 ID 接续之前，完整原始请求必须成功保存到本 profile 的浏览器存储。首次快照尚在读取时也必须先合并本 profile 已有的待查回及保留记录；新操作或只读查回不能覆盖旧 ID。保存失败明确表示请求未发送，保留可见原请求和当前草稿；不能继续发写入，也不能声称操作已持久保存。

原操作只读查回不依赖新的浏览器写入。已经返回确定回执后的本地清理失败不能把已完成操作改称未知或未执行。将请求“保留并收起”时，先成功保存历史再移除待查回项；任何存储失败保留可恢复的原 ID。历史与待查回重复的同 ID 不授予新的执行许可。

成功刷新只清除同一次刷新流程留下的旧连接错误；刷新等待期间较新的修改、查询或版本错误必须保留。修改被接受后，若已有轮询或目录刷新尚未完成，等待该读取结束再获取提交后的新 snapshot；不能将提交前的读取结果作为修改后的最新对象，也不强制重读未变的模型目录。

## 3. 群聊来源持续有效

`viewGroup` 对最终实际返回的可读消息调用既有 `noteDerivedRead`，包含原会话、资料来源与 origins。内部群 prompt 先筛可读消息，再取最后 30 条，再记录真正消费的依赖；不记录未使用的旧消息。

下一成员使用真实群回复形成的会话、资料或记忆须保留来源依赖；撤销原来源后阻止后续读取、请求与发布。保留原生日志和资源结算证据。升级不根据猜测改写旧记录的未知历史来源；本修复保证新的实际消费链路。

## 4. 跨资料块检索

保留现有无重叠 800 码点分块、chunkId、内容哈希与原文引用。搜索补充相邻块边界候选，能检出跨边界的中日韩词、英文词及短语。结果仍返回真实原块和精确偏移／行号，不伪造一个无法打开的新 chunkId。

只在当前有权读取、未归档的资料上计算和排名；命中数受既有 limit 约束，排序稳定，不调用模型。没有真实跨界匹配时不得提升不相关邻块；Unicode、CRLF 以及撤销共享后的隐藏行为保留。

## 5. 停止状态与提醒游标

停止父工作时，真正持槽的父／子尝试、对应原生会话与各自当前任务同时显示正在停止；保留确切原 attemptId／epoch，等待真实结算。不把已经结算或后来尝试的任务误改为停止。

只编辑提醒内容、启用状态或漏发策略而未改变规范化规则时，保留原 nextDueAt／nextTriggerKey。暂停后已过期的单次提醒在恢复时按原时间显示迟到通知，不因编辑文字被无声取消。改变规则或切换提醒／任务类型时按新定义计算；已触发项不重复，定时执行任务的原 consent／UNKNOWN 边界不变。

实际官方 GUI 在已有安排的环境复现了编辑后重复卡片：列表卡片与编辑器共享同一个 React sibling key。编辑器使用独立 key 命名空间，原 scheduleId、版本和操作回执不变；用三个已有安排加一个待编辑提醒核对存储和页面都只保留四项，目标提醒仅显示一次，恢复后也只通知一次。

## 6. 交付验收

每项先记录旧行为的失败复现，再实现最小修复；保留现有回归。对真实安装的新版增加聊天接续、跨块搜索、存储失败和提醒恢复检查。升级覆盖全部七条旧路径及当前稳定 v1.1.4，核对原身份、内容和操作回执。

独立任务复审及全分支复审闭合后提交 PR；实际分支／PR、合并后的 main、正式标签分别通过完整 Linux／macOS CI，再发布新版中文 GitHub 页面并匿名验收正式下载与校验。
