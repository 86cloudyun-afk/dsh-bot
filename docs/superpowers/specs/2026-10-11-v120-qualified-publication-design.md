# v1.2.0 受限发布流程

状态：依据用户持续授权自主完成 PR 审查、合并和 GitHub 正式发布。命令行凭据真实返回 401；已连接 GitHub 工具仍可提交与合并，但不提供标签、Release 或 workflow dispatch 写接口。

## 目标与边界

使用仓库提供的 `GITHUB_TOKEN` 完成两个显式发布阶段，不读取、导出或替换任何用户凭据。插件的 30 个文件与已验收包保持原字节；本流程不进入原生插件包。只服务本轮 `v1.2.0`，保留旧标签、失败、资产和原回执。

## 授权与准入

只有仓库所有者 ID `269269188` 在已合并的 PR #11 上新建的精确命令可启动。连接实际创建的评审评论已通过公开 API 确认作者身份；编辑评论、其他作者／仓库／issue、错误版本和不完整命令不能写入。工作流从默认 main 获取可信代码，关闭 checkout 持久凭据；命令不作为 shell 代码插入。

命令绑定准确的 main SHA 与实际验收 run ID。流程核对当前 main、默认分支、工作流路径、实际事件／分支／源码、终态、七个成功原生 CI job 与新增发布守卫 job、两平台九份严格报告、最终清理、零外部模型请求及冻结包 `43e837624194596a9ff679e86b68f416ea7977152f480191c208fc5eae726d94`。未完成、未知或不一致的证据拒绝发布。

## 两阶段

1. `/dsh-bot-tag v1.2.0 <mainSHA> <mainRunId>`：在完成并独立复审 main 验收后建立不可移动的注释标签。已有标签只读核对，任何不一致拒绝。由 `GITHUB_TOKEN` 创建的标签不会触发 push CI，因此显式 dispatch 既有原生 CI，ref 为 `v1.2.0`；CI 增加 `workflow_dispatch`，原 push／PR 和所有检查保持。
2. `/dsh-bot-publish v1.2.0 <mainSHA> <tagRunId>`：标签上的新 CI 完成并独立复审后，核对实际 dispatch 事件、标签分支、源码和全部原生报告，再发布中文稳定／latest Release。沿用已确认的 notes-only 交付，包和 SHA256SUMS 链接指向不可变公开标签，不上传额外资产。

标签 CI 的 dispatch 携带注释标签所记的原评论与发布 run ID；CI 名称绑定两个 ID，守卫核对实际 `refs/tags/v1.2.0`。发布核对该运行晚于标签创建、早于本次发布评论，拒绝同名分支、早于标签的运行和缺少本次标识的手动 dispatch。实际交付使用 dispatch 响应返回的准确 run ID，由独立复审后写入发布命令。每次写入前重新读取原评论、main 与标签，拒绝已编辑／删除的命令或变化的来源。

网络写入失败保留已发生的标签／发布事实；不删除、移动标签，不把未知结果称为成功。不自动重放不确定操作；再接续时先只读查询远端唯一对象。

## 验证与交付

先用实际失败边界驱动发布守卫测试，包含错误身份、事件、SHA、run、报告、包、标签及部分完成状态；写入调用必须在全部验证后发生。独立审查流程权限、信任来源、注入与失败边界。通过现有连接提交单独 PR，验证原生 CI 与发布守卫，再审核合并。最后执行两个已授权命令，分别独立核验新的 main 和真正标签 CI，匿名检查稳定 Release 与下载。
