# v1.1 日常助理、简报、定时与诊断

状态：按用户授权实施，最终以 PR 复审与原生验收结果交付。全局约束见 [总规格](2026-10-09-v1.1-native-upgrade-design.md)。

## 1. 原生聊天与任务简报

复用官方 `uiWorkspace.openSession` 和 additive slots：`conversation.session.header.utilities`、`conversation.session.header.actions`、`conversation.input.dock`，以及 sidebar row hover／menu。进度入口与摘要不得遮挡原生运行／停止／新消息标志，不修改原生会话日志来模拟完成。

当前 Bot 的原生联络聊天中显示紧凑任务简报：任务标题、真实尝试状态、已保存结果预览、验收状态和打开执行／任务详情入口。预览最多 800 个 Unicode 码点，取自已提交 report／result，不额外调用模型总结。进行中只显示已知状态，UNKNOWN 明确标注，停止已接受仍显示等待结算。

新增持久 `notices` 保存结果和提醒的身份，不冒用原生 completionUnread（它为进程内状态，不能任意写入）。结果 notice 的唯一键由 storeId、taskId、attemptId、epoch、outboxId 组成；展示、查阅、确认已读分开。`notice.ack` 必须带 noticeId 与 expectedVersion，确认旧结果不能清除更新尝试的未读状态。已读写入不触发模型、不停止任务。

界面可在聊天标题显示未读数／简报入口，在任务页查看提醒。浏览器重新打开、宿主重启、插件禁用后再启用均保留未读和已读。摘要与 notice 的可见性仍由实际结果 origins、会议阶段与当前共享范围决定；不能通过通知泄漏隐藏任务的标题或内容。

## 2. 提醒与定时任务的范围

支持单次、固定间隔、每日、每周规则；不提供 cron 编辑器。保存 IANA 时区、用户选择的当地日期／时间、对应 UTC dueAt 和规则版本。新建时区取客户端实际时区，本用户界面默认北京时间 `Asia/Shanghai`，可修改并明确展示。

- 提醒：到期生成插件内通知，不启动 Agent／模型，不调用原生 followup。关闭 DSH 时不运行；恢复后显示原时间和迟到标记。
- 定时任务：经过认证的负责人确认一个不可变任务配方，包括负责 Bot、标题、目标、验收条件、可选 dependsOn 和结果接收会话。每次触发登记独立、关联到 schedule 的真实任务和尝试，保留自己的结果与验收；不复用已有运行尝试。配方中前置任务的当前有效验收在每次开始时重新检查。
- 自然语言提出提醒或任务时，Bot 可形成自己的草案。草案不是持久执行许可。启用定时任务由人类或经过认证的所属 Bot 明确提交，展示负责 Bot、频率、目标、模型及接收位置；原生工具审批继续生效。

限制：每 profile 最多 100 个未归档 schedule；固定间隔至少 15 分钟；每个 schedule 同时最多一个未结算工作。定时功能不占用新主导航，在任务页的“提醒与定时”展开。

任务错过执行默认“跳过并提醒”；可以在明确确认时选择“恢复后补最近一次”，只补一次，不倾倒历史队列。普通运行超过 dueAt 60 秒未准入视为错过。明确启用补做时，重启选择最近一个未准入周期，在持久 recoveryObservedAt 之后额外给一次 60 秒补做准入窗口；保留原 occurrenceId／dueAt，不生成替代旧工作的身份，重复重启不刷新窗口，已有 claimed／UNKNOWN 的周期不纳入补做。提醒恢复后只生成一条原触发身份的迟到通知。任务配方／时区／频率改动递增 consentVersion，旧 occurrence 不变。每 profile 最多保留 10000 条 occurrence；达到上限停止接纳新触发并提示导出／清理历史，不静默删除、覆盖或放弃 UNKNOWN。初版的历史清理仅允许已结算／missed 且无待查回引用的记录，由人类明确确认；原任务与操作回执不因此删除。

每日／每周在夏令时缺失的当地时刻跳过并记录原因，重复的当地时刻只选较早 UTC 映射；一个当地日期和规则版本最多一次触发。固定间隔按已保存 UTC 序列计算，时钟回拨不重复已认领 occurrence。

## 3. 授权与触发身份

`schedules` 保存 scheduleId、ownerBotId、规则、recipe、version、consentVersion、enabled、nextDueAt、missedPolicy、executionConsent 和创建来源。executionConsent 由真实已认证人类或所属 Bot 的操作写入，绑定配方摘要、负责 Bot 的 configRevision、允许动作和确切接收会话；数据库中的任意 `kind:human` 标签不是权限凭证。

`occurrences` 保存稳定 occurrenceId（scheduleId＋consentVersion＋规则触发键）、dueAt、claimVersion、固定 create/start operationId、taskId、attemptId、状态和真实回执。限定状态为 planned、claimed、running、settled、missed、blocked、UNKNOWN。所有准入前先持久认领；同一 occurrence 只创建一次业务身份。

定时控制器使用内部受限准入接口，PermissionPolicy 检查有效 schedule、当前 occurrence、executionConsent 与输入匹配。不得把保存的 caller 标签转为人类／Bot actor，不得调用 `fromPeer` 冒充新的人类操作。内部许可只能创建该配方的根任务、开始其首次尝试，并按固定目标记录结果；不能修改授权、Bot 身份、共享、其他任务或普通会话。

每次准入检查 Bot active、配置版本、实际模型可用性、结果接收会话仍可用、所依赖内容仍可读、15 槽及深度限制。配置或接收目标发生变化时暂停并要求重新确认，不能静默改模型。配方含有的资料引用执行当前来源授权和会议屏障。

结果和尝试继续使用既有 TaskController／ConversationBroker 的身份、停止和结算机制。内部定时 principal 在账本中有专用受限来源，不伪造 `createdBy:{kind:human}`；结果发布再次验证原许可与目标。撤销后可保存真实结果，但不向被撤销目标发布。

暂停／取消／撤销先封住新准入，保留已准入任务和 UNKNOWN；若要停止在途工作，用户使用该真实任务的停止操作。不能因删除 schedule 自动删除尝试证据。

## 4. 生命周期与失败行为

只持有一个生命周期所属的最近到期定时器。保存变更后重算；长等待分段，唤醒时重新检查时间。退出插件先取消 timer，再排空已接纳业务写入／工作，最后关闭存储。

重启只查回原 task／attempt／operation 的证据。原生准入前后丢回执均保留原 IDs；UNKNOWN 不能自动重发、不能释放槽、不能用新的 occurrence 包装重试。能够证明未准入的 blocked 情况可在原身份下重新检查。恢复后的新周期不绕过未结算 occurrence。

notice 展示的“已提醒”“任务已结算”“验收通过”分别有真实证据，不将通知送达冒充工作完成。读取定时列表、历史和诊断不唤醒 Agent。

## 5. 诊断

管理页新增“复制诊断”，本地只读生成允许字段：插件／服务／协议／DSH／Node／平台版本、profile 不透明标识、功能可用状态、对象数量、当前错误码与阶段、用户选中的原操作 ID。

不包含模型密钥、Authorization、启动鉴权 URL、绝对路径、聊天／任务／记忆／资料正文、原始请求参数、cookie 或环境变量。诊断预览与复制内容一致，不上传、不替用户发送给其他人。未知错误默认仅给通用说明和错误码，禁止直接转发完整异常／SDK boot log。

## 6. 必须覆盖的验收

- 原生扩展与官方控件并存；浏览列表和简报不泄漏 Session retain 或启动模型。
- 真实提交结果才生成对应 notice；旧已读确认不能清掉新结果；跨浏览器／新宿主进程仍一致。
- 权限撤销和封存意见使摘要不可读，已读与未知状态不掩盖真实资源。
- 提醒产生零模型／工具请求；定时任务只使用一次准入身份，受容量、配置和审批约束。
- 单次／间隔／每日／每周、IANA 校验、DST 缺失／重复时刻、回拨和延迟唤醒。
- pause／cancel／修改与认领并发，修改草稿 CAS，旧 timer 在禁用后不再准入。
- 重启前后原生准入崩溃与丢回执；UNKNOWN 零自动重放且保留槽位。
- 错过周期只跳过并提醒或补最近一次；未结算旧 occurrence 不产生新并行工作。
- 保存的 actor 标签、导入 JSON、未确认草案不能触发受限准入。
- 诊断中注入密钥、URL、路径和错误消息，复制输出不出现这些内容。

恢复使用有界触发游标和 missedRange 摘要，不逐条枚举长时间停机的历史；只物化原下一到期及选定最近可补周期。暂停、重启和恢复不能刷新已经保存的 recoveryObservedAt。
