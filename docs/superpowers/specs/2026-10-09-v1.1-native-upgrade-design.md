# DSH Bot v1.1 原生插件升级规格

日期：2026-10-09（北京时间）。状态：待用户评审的设计稿，尚非已实现或已发布能力。

## 1. 目标与已授权范围

用户要求在上一轮日常助理升级建议上，同时加入协作与知识增强，使用 Superpowers 流程开发，提交 PR，多轮审核无误后合并更新。本规格将这些能力分为三个可独立实现、验证的模块，最终交付同一个 `dsh-bot` v1.1.0 插件。

- 日常助理：记忆管理、聊天中的任务简报与未读结果、主动提醒和定时任务、脱敏诊断。
- 协作增强：Bot／团队模板、任务依赖、明确的责任交接。
- 知识增强：资料收录与检索、真实来源引用、单 Bot 记忆导入导出。

本轮用户没有要求另建网站、修改 DSH 本体或启用新的实验性宿主组件。保持官方原版 DSH 插件路线；旧独立软件继续作废。

## 2. 全局约束

1. 官方基线仍为 `@deepseek-ai/dsh@0.2.0-rc.2`，Node `^22.19.0 || >=24`；Linux 和 macOS 均须验证同一冻结安装包。
2. 只使用官方公开接口；包不携带或改写 DSH／Host／SDK。无需启用官方实验性定时 bundle。
3. 每 Bot 独立身份、记忆、会话与职责。跨 Bot 读取执行当前共享上限，控制授权持续有效且可撤销；新模块不得绕过会议封存意见的可见性。
4. 工作工具默认沿用 DSH 当前可用工具及其原生审批。模板、定时任务和知识页均不恢复工具白名单设置。
5. 父工作、一级子工作、未结算 UNKNOWN 共用每 Bot 15 槽，子工作仅一级。后台工作不占用独立联络通道。
6. 接受停止与实际结算分开。未知准入、未知结果或丢失回执保留原身份，不换 ID 重放，不提前释放工作槽。
7. 保留五个主导航：Bots、任务、记忆、协作、管理。新增功能放在相应页面及原生聊天扩展位置，特殊选项折叠。
8. 已确认的 v1.0.1 草稿、版本检查、原操作查回和显式接续行为保留。v1.1 工作台／服务声明版本 `1.1.0`、协议 `2`，不匹配时写入前拒绝。
9. 不因展示简报、搜索资料、复制诊断、模板创建或导入预览发起模型请求。任务开始或用户主动对话产生的用量记录沿用真实证据，未知用量仍为 UNKNOWN。

## 3. 方案选择

采用单一插件内的明确业务模块，复用既有 TaskController、ConversationBroker、PermissionPolicy、PluginStore 和原生 Session。

官方定时服务在普通 profile 中默认未启用，其文档承认投递和账本更新间的重启重复窗口。直接接入它会改变现有不重放承诺，因此本版使用插件生命周期内的定时器和持久触发记录；外部 DSH 进程关闭时不运行。每次触发的授权与身份见日常助理规格。

知识检索先采用有界的文本／Markdown 和明确授权的原生会话片段，提供词法检索与准确引文。PDF／Office 等资料可先通过 DSH 已有工具提取正文后收录；本版不新增二进制解析、云端知识服务或 embedding 依赖。

协作扩展复用现有群和任务，不引入第二套项目／工作流执行引擎。任务依赖控制明确开始的准入，责任交接在真实结算后完成。

PermissionPolicy 新增内部只读 `canProspectiveBotRead({botId,purpose,lineage},reference,draft)`，用于执行 Agent 尚不存在时的依赖输入、交接接收者与定时配方来源检查。botId 必须为真实有效 Bot，purpose 仅 contact／execution，lineage 来自控制器验证后的真实任务／绑定而非 RPC 标签；执行当前共享、来源及会议屏障。它不注册 actor、不产生命令权限、不创建会话、不记录虚构的实际读取。尚不存在的目标 Session 不享有任何独立意见通道的 own-channel 特权，不能借用调用者的封存可见性。实际 Agent 建立后每次请求／工具／结果仍使用正常认证策略，不能用预检代替运行时检查。

## 5. 升级与持久数据

基线为已合并、发布的 v1.0.1。v1.0.0 和 v1.0.1 均须以官方插件命令安装升级，完全退出旧宿主，再以新进程打开同一 profile；刷新浏览器后核对两端版本。

内部账本升级为 schema 2，保留原 storage namespace、KV descriptor version 1、storeId、全部 Bot／会话／任务／尝试／操作／投递身份。新表为 `materials`、`schedules`、`occurrences`、`notices`。模板目录随代码提供，不复制运行态。迁移为同一 `state/current` 持久记录的一次原子写入：schema 2 中嵌入只读 `migrationBackup:{schema:1,checksum,payload}`，payload 是迁移前完整有效 schema 1 状态。校验绑定原 storeId 和 revision；完整性检查失败不得写入。原子写入前崩溃仍为原状态，之后崩溃则为完整新状态与备份，不使用更换 namespace 或 descriptor version 来生成空账本。

旧任务缺少的新字段以空依赖／空交接记录解释；保留已有 definitionVersion，不将旧验收无依据地升级成可解锁依赖的证据。旧 Bot 的新增资料共享范围为 `[]`，关闭共享和选择性共享均保持；用户可以明确启用资料只读共享。新建 Bot 的资料共享默认只读。

迁移不能触发任务、唤醒所有会话或重放待查回请求。原始操作 ID 和原调用者指纹保持可读查回。版本未知、未来 schema 或损坏账本均拒绝覆盖。schema 2 不承诺旧插件原地降级读取；需要回退时使用迁移前备份和原版，不能把旧运行态恢复后自动当作新工作再次执行。

## 6. 审核与发布门槛

实现前完成这组书面规格评审，再分别生成实现计划。开发按模块执行 RED→GREEN，复用既有测试夹具和官方原生 GUI；独立评审覆盖权限／来源、业务运行与用户操作三个角度。

本稿已完成三个领域的只读源码／官方接口研究、一轮自审与一名独立规格评审。独立评审提出的补做时限、Bot 资料来源和未启动 Agent 的可见性三项重要问题，已在各模块与上述策略接口中明确；这只证明设计问题已收口，不代表功能实现或测试已经通过。

| 验收 | 必须通过的证据 |
| --- | --- |
| 既有功能 | v1.0.1 的 180 项回归基线，以及新增功能对应测试；无跳过或隐式降低断言。 |
| 并发与恢复 | 多页面草稿冲突、重启、暂停／取消与准入竞态、丢回执、UNKNOWN、旧停止及迟到结果。 |
| 身份与权限 | 默认只读、授权撤销、依赖来源撤销、会议封存、旧运行日志归属、导入数据不能产生调用者权限。 |
| 原生 GUI | 两平台同包全新安装：创建 Bot、聊天与后台短／长任务、模板建群、依赖、交接、资料、定时、诊断的实际操作。 |
| 升级 | v1.0.0→v1.1.0 与 v1.0.1→v1.1.0 的新进程验收，身份／记忆／原操作／共享范围不丢失、不扩大。 |
| 分发 | 包内文件与当前源码逐字节一致、MIT 存在、敏感内容复扫、公开下载 SHA256 与 CI 冻结包一致。 |
| 合并 | PR 必须指向实际最终实现，检查与独立复审无未关闭的重要问题；验证 exact head 后才合并，再验证 main 并发布。PR #1 继续保持未合并。 |

受控模型、外部真实模型、只读检查、调用量与 UNKNOWN 证据分别记录，不将旧版实测冒充新版实测。规格 PR 为草稿，不提供 v1.1 安装包，也不改变当前推荐的 v1.0.1。
