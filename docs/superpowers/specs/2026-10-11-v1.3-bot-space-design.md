# v1.3.0 Bot 空间设计

## 目标与已确认约束

用户要求一个有高设计感的专用窗口，能够持续与具名 Bot 对话、使用多个 Bot、群聊和协作，并授权自主完成工程、复审、合并和发布。日常聊天必须成为中心，而不是让用户在多个管理表单间跳转。

- 官方未修改的 DSH `0.2.0-rc.2` 原生插件；不创建独立 Host，不修改 DSH 本体。
- 产品目标版本 `1.3.0`，schema 2、clientProtocol 2；保留 v1.2.0 的原 Bot／会话／任务／消息／操作 ID 和历史。
- 每个 Bot 独立记忆、后台工作与联络聊天分离；已有 15 工作槽、一级子工作、权限和可撤销共享语义保留。
- 所有验证使用隔离官方 profile 和受控提供者，外部模型调用为零，不访问用户 Host。
- UNKNOWN 不自动重放，不换 ID 掩盖失败；完整原请求先保存，原回执与失败证据保留。
- v1.2.0 稳定包、所有旧包、标签和发布物保持原字节；PR #1 仍关闭未合并。

## 方案与窗口边界

选择官方 `main` keyed panel 中的专用三栏 Bot 空间。双栏加详情抽屉可作为窄屏呈现；不采用多 Bot 并排消息墙，避免日常阅读拥挤。

官方公开 `conversation.content` factory 支持 `variant: embedded`；原生 Session 的消息、历史、实时输出、输入、排队、停止、工具呈现和审批均由它提供。官方没有已确认的 OS 子窗口 API，因此本版“专用窗口”是 DSH 内可单独选择的完整插件面板，不声称桌面分离窗口。

左侧 DSH 导航新增 **Bot 空间**，panel key `dsh-bot.space`；已有 **Bot 工作台** 保留作为完整管理入口。旧工作台的行为和原生会话入口保持兼容，Bot 空间成为新的日常聊天入口。

## 视觉与布局

- 空间左栏 248px：品牌标题、搜索、创建入口、Bot 与所属历史、群列表，底部管理与原操作入口。
- 中央：固定身份标题、真实聊天、底部原生输入区或群消息输入区。正文最大宽度 760px；身份及模型说明跟随真实选中对象。
- 右栏 296px：当前 Bot 的任务、记忆／资料与身份；群的成员、真实会议和会议行动任务。可收起，不能把成员的全部私人任务冒充群任务。
- 容器宽度不足 1180px 时右栏收起；不足 840px 时左栏变成可关闭的会话抽屉；小窗口保留“会话”“上下文”入口。
- 主色深青绿 `#146C62`，选中项浅色层次、1px 分隔与适当留白；正文沿用宿主字体与主题色，支持深色模式。空间标题 20px，身份 18px，正文 15px／1.75，辅助文字 12px；8px 按钮圆角、12px 输入区圆角，点击区域至少 40px。
- 头像取名称首字和稳定 ID 对应的柔和色；头像颜色不代表在线。使用文字明确说明实际状态，不伪造进度百分比或回复时间。
- 自定义样式局限于 `dsh-bot-space` 与 `bs-` 子元素，不能覆盖其他插件或重写原生工具审批控件。

## 私聊、选择与生命周期

浏览 Bot 不写业务数据、不启动模型；没有历史时呈现 Bot 的身份和“开始新对话”。已有可用聊天按稳定 botId/sessionId 显示原名称与 ID；用户明确选择后打开原会话。

专用 panel 声明 Session-scoped 子槽 `dsh.bot-space.conversation`。选择真实 ready、未归档的 contact 后，经官方 `sessions.retain(sessionId, {source: botSpace})` 取得引用，在 Effect 中持有，并将 **reference** 传给 framework `SessionProvider`。通过子槽调用官方 `renderFactorySlot(conversation.content, {variant: embedded, phase, hero})`，局部固定 `conversation.session` 的 chat 视图。等待 reference.ready 后只激活该 binding 的 chat view，不修改 DSH 主会话 current。

切换对象立即移除旧会话 Provider；retain/release 对称，处理同步抛错、ready 拒绝、profile 改变、插件销毁、连接 generation 变化和迟到结果。选择保存只在当前 store 范围内有效；服务端与前端实时 snapshot 都必须仍确认对应 Bot／会话可用。新建聊天通过已有 command(session.create)，写入前保存完整原请求；只打开回执中的原 sessionId。标题中的有效 provider／model 使用所选真实会话配置，缺少会话配置时才成对退回 Bot 默认值，不能拼接两个来源的模型身份。

原生草稿由官方 inputHub 管理；跨 Bot 不串草稿。非原生群输入草稿按 storeId/groupId 保存于插件组件的内存状态，提交失败保留正文；成功回执只清理对应原群、且正文仍与原提交一致的草稿。中文输入法合成中的 Enter 不触发发送。

## 多 Bot 与群聊

空间可以创建具名 Bot：名称、职责、模型；模型默认沿用 DSH 当前有效配置，其余设置按需展开。新群选择名称、已有 active Bot 和协调者；协调者必须是被选成员。创建群本身不启动模型。

发送群消息调用已有 `group.post({groupId,text})`。人类消息启动真正有界群轮；Bot 回复来自真实独立原生通道的已完成模型事件。成员数 1–15，轮数 1–3、默认 1，请求预算 1–60、默认 12；沿用后端限制，不做无限自动循环，不添加虚构的 @ 定向路由。

群消息按真实 messageId 展示发言者和正文。snapshot 已返回权限过滤后的全部群消息；初始显示最近 40 条，“显示更早消息”每次增加 40 条，直接使用当前真实 snapshot，不伪称服务端分页。新写入原子限制 2000 条：人类／Bot 主动消息和模型回复全部在事务中检查边界，新成员通道亦预先检查；在途结果未能发布时保留真实原生日志和原因。旧版本已超出此数的历史全部保留，不为满足上限截断。群模型上下文的最近 30 条边界与 UI 历史展示分开。

滚动在底部时跟随实际新消息；上翻后保留位置，显示新消息入口。没有 time 的历史 Bot 消息不补造时间。缺席、预算用尽、正在回复、停止中、已停止、未知分别依据真实记录呈现。

### 新增群轮停止

新增人类动作 `group.round.stop`，输入严格为 `{groupId,roundId}`，保留 operationId 幂等和当前身份检查。仅停止确切选中的已有群轮，不停止其他群轮、私聊或任务。

在持久意图中将当前本 runtime 的 running 群轮变为 stopping；阻止新成员 channel、创建等待后的 followup 与迟到回复发布。对全部属于该群轮的原 channel 调用真实 adapter.stopResources，并等待／核对资源结算证明，才转为 stopped。未结算保持 stopping；无法证明身份／资源结果则保留 UNKNOWN，不释放或重新启动未知工作。

停止与轮正常结束的竞态以当前持久状态为准；不能把 stopping／stopped 覆盖成 complete。重启后的 stopping 与原 running 同样按旧 runtime 保守标为 UNKNOWN。群队列计数和 Bot 删除等生命周期检查必须包含停止中、未结算轮。原消息、source、usage、成员 epoch 和请求计数不擦除。

## 任务与会议协作

私聊右栏只显示当前 Bot 的真实任务；“新任务”输入标题、目标、验收条件，先 task.create，再通过返回的 taskId/version 明确 task.start；创建／启动反馈不等于任务完成。停止使用当前 taskId/attemptId/epoch。原生执行会话与完整任务管理可从相应条目打开。

群右栏展示本群真实会议。会议可在空间内通过现有 meeting.start 开始、meeting.advance 推进、meeting.cancel 取消；提交输入捕获原 epoch／phase，冲突时保留草稿而非自动改成新 epoch。独立意见按既有原生访问策略揭示：当前 discussion／decision／complete 阶段属于已经揭示的会议，兼容没有 revealedEpoch 字段的已支持旧记录；cancelled 阶段只有 revealedEpoch === 当前 epoch 才显示。独立阶段取消、未揭示或旧 epoch 继续只展示收集人数与封存状态，不能把所有非 independent 阶段一概认作已揭示。

会议行动通过 meeting.action 关联到决定并创建实际任务；不假定创建即已运行，也不宣称结果自动群播。群的行动任务只由本群 meetings.actions 的 taskId 归属。高级议题／成员配置、依赖、交接、验收及权限编辑继续在完整管理入口中完成；onManage 接受 botId／taskId／groupId／meetingId，选中正确子页并定位相应稳定原对象。记忆管理必须选中当前 Bot，UNKNOWN 群轮查阅必须定位原 groupId，不能退回列表第一项。

会议 cancelled 表示逻辑取消，UI 不称资源已结算；保留待停止或待确认工作提示及原通道记录入口。

### 群与会议的原生交互

官方 Gateway 会为来源 Agent 的 Remote 请求临时保留 history-free scope，并将真实待确认交互发布到全局 uiSession.sessionStatus，不要求先选为主会话。空间订阅该只读状态，结合持久 channel lineage 与当前群轮／会议 epoch／成员 epoch，显示确切 Bot、群轮或阶段的“待确认操作”。选中其他群的待确认数可以在相应群列表提示，但不能将它渲染为当前私聊审批。

点击待确认操作后，才为其真实原 channel retain 普通 botSpace 引用，在自有 Session-scoped 子槽 `dsh.bot-space.interaction` 的 Provider 内调用官方 conversation.content embedded factory。普通 retain 会打开和缓存该会话历史，并非 history-free；局部 views 覆盖为空、hero 为 false，阻止消息、推理、原生历史及独立意见正文的渲染，保留官方 composer takeover。原生 ApprovalPanel 仍显示请求者提供的 reason／displayReason 和工具命令，这些字段可能包含业务正文；插件不改写审批信息，也不宣称它们能被 EmptyView 清洗。

工具审批入口仅在所捕获的确切真实 pendingInteraction 满足 kind='approval'、key／sessionId 和对象身份一致、answerable===true，且 lineage／epoch 仍有效时挂载。答复导致 answerable 变 false 时即卸载，不等发布项消失；停止／取消、换阶段或交互变化同样立即卸载，不能露出发送新消息的常驻 draft fallback。原生提问与计划确认采用各自官方公开交互契约单独验证，不能把任何未知 pending kind 当作工具审批。

不声明官方已拥有的 conversation.composer 子槽，不注册竞争审批消费者，不伪造 PendingApproval，不绕过原生审批。需要实际群成员和 independent 会议成员工具调用的 GUI 证明：确切 tool／approval audit、正确 Bot 归属、真实答复后继续执行或拒绝后中断，且独立意见仍封存。

允许调用原生提问工具的群成员／会议讨论通道还必须能够回答官方 question 与 plan-review 交互。它们使用官方 PendingQuestion 公开 snapshot／subscribe 契约；不能伪造 approval.answerable 属性。原生隐藏、超时、转为继续回答、计划讨论与真实结束分别依据官方状态处理；隐藏的具名请求需要通过公开 userQuestionPanels.reveal(sessionId,callId) 恢复。仅匹配当前精确通道和有效交互时嵌入原生控件，未匹配或已结束时不能渲染普通执行会话输入区。实际 SDK 契约与真实 GUI 分别验证。

先订阅真实 canonical question／plan-review 对象（包括 channel none），再判断可提交状态。Factory 要求当前发布项仍为同一对象，并且公开 snapshot 为未 closed、无 review 的 open/waterfall 或 continued/rpc。隐藏的具名交互保留当前世代的真实 handle 与订阅，以明确按钮重新打开，不自动覆盖用户关闭行为；已结束／换群／换世代立即清理。原生“讨论”执行 dismissal：具名请求隐藏，未具名请求取消；它不是提交拒绝或确认完成。未知历史隐藏卡不能被公共 SDK 枚举，因此不承诺恢复未观察到且无持久投影的任意旧交互。

对选中群／会议的当前 ready 通道，以公开 refreshProjections 取得每连接首次 baseline，观察 userQuestions active 的真实 continued 行；仅持有受影响通道的短期 botSpace reference，让官方 binding 生成原有 continued carrier，并在无待交互、离开范围或换 generation 时释放。停止／完成的群轮、已 settled／UNKNOWN／归档的通道、旧 phase 或成员 epoch 均不恢复，不用晚答绕过执行准入。读取投影和持有引用不创建模型请求、不改变原工具结果。

原生 question/detail/plan 是请求自身必要内容，EmptyView 不清洗它们。空间显示当前 canonical questions[].detail 的完整原文，安全转义、只读，不读取历史或虚构 pending.plan。原版 ui-plan 的全局 sidebar 在 Bot 空间 activePanel 下没有 mounted surface，不能用其 openResource 或切换 DSH 主会话来冒充嵌入预览。激活官方 ui-plan；仅在确切 live plan 交互面板拥有生命周期时，使用官方公开 list-cell shadow 将 conversation.plan-review.actions 的原 ui-plan ID 以 priority -1 空组件暂时覆盖，面板退出立即 dispose 恢复原 priority 0。原生 approve／discuss 保留，计划全文在本面板读取；以真实全文／讨论隐藏／重新打开／确认／工具结果、无主会话切换和原生 entry 恢复证明此边界。

## 操作反馈与可访问性

所有空间业务写动作复用现有 command 保存／兼容／查回路径；不建立第二份写入实现。当前错误、存储失败与待查回原操作就近显示，提供完整管理与原操作入口，刷新不重发。

弹层与抽屉有明确标题、关闭按钮、Esc 和返回触发点；所有图标有中文可访问名称，焦点清晰。群发送按钮始终可见，尊重输入法合成；不可用对象显示原因。任务／消息变化不强行夺取焦点。

## 组件与构建

保持单一浏览器 ModuleLoader factory，避免未经支持的包内 runtime require。新空间逻辑在 `src/client/bot-space.js`，样式在 `src/client/bot-space.styles.js`，由确定性 `scripts/build-client.mjs` 内联到当前 `src/client/client.js` 明确标记区域。`--check` 逐字节验证生成内容，CI check 必须拒绝过期输出；产品包仍只分发自包含 client.js，不增加构建期依赖。
