# Restricted Owner App Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Provide an actual native-launcher, OS/runtime-owner stdin entry over the existing private controller, without new persistent access or authentication.

**Architecture:** A startup plugin parses launcher flags before the zero-tool profile activates. The app retains the actual fiber privately, prepares original-ID commands through the existing ledger/controller, and binds teardown to native app lifetime. Offline setup stages public fixed artifacts at one package root and creates a fresh independent profile.

**Tech Stack:** Node 24.19.0 (DSH requires ^22.19 || >=24), fixed rc.2 native artifacts plus protected candidate `3fbedc25`, Cordis 4.0.4, existing SQLite/native controller.

**Spec:** [owner app design](../specs/2026-10-04-owner-app-design.md).

## Global Constraints

- No new real model/API requests or model tools in this round; old 12 SQLite/WAL/SHM files unchanged.
- No new token, BrowserAuth, account, role/scope or permissions; no listener, daemon, push or merge.
- Keep actual fiber private; no actor/caller/grant JSON and no verified-human claim.
- Fresh independent test Homes; actual dsh profile launch; default model requests disabled.
