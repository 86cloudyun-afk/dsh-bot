# 安装 DSH Bot 原生插件

插件安装在你现有、未修改的官方 DSH 内。模型凭据、工作目录、审批和原生会话沿用 DSH 配置。

## 1. 检查宿主和安装依赖

兼容基线：Linux／macOS、官方 `@deepseek-ai/dsh@0.2.0-rc.2`、Node `^22.19.0 || >=24`。官方插件管理器通过 `pnpm` 安装依赖；验收固定使用 `pnpm@11.19.0`。

```bash
node --version
dsh --version
pnpm --version
```

尚未安装官方 DSH 时，先按官方说明完成安装和模型配置。npm 安装方式为：

```bash
npm install -g @deepseek-ai/dsh@0.2.0-rc.2 pnpm@11.19.0
dsh web
```

确认普通 DSH 会话可以发送消息并获得模型答复，再安装本插件。已有 DSH 的用户只需补齐缺失的 `pnpm`。

## 2. 获取并验证插件包

在 [GitHub Release](https://github.com/86cloudyun-afk/dsh-bot/releases/tag/v1.3.0) 中打开 [插件包](https://raw.githubusercontent.com/86cloudyun-afk/dsh-bot/v1.3.0/dist/dsh-bot-1.3.0.tgz) 和 [校验文件](https://raw.githubusercontent.com/86cloudyun-afk/dsh-bot/v1.3.0/dist/SHA256SUMS) 链接保存；也可以在下载目录运行：

```bash
curl -fLO https://raw.githubusercontent.com/86cloudyun-afk/dsh-bot/v1.3.0/dist/dsh-bot-1.3.0.tgz
curl -fLO https://raw.githubusercontent.com/86cloudyun-afk/dsh-bot/v1.3.0/dist/SHA256SUMS
```

Linux：

```bash
sha256sum -c SHA256SUMS
```

macOS：

```bash
shasum -a 256 -c SHA256SUMS
```

应显示插件文件校验通过。Release 同时提供兼容版本、源代码身份和 [本版说明与验收状态](https://github.com/86cloudyun-afk/dsh-bot/blob/v1.3.0/docs/releases/v1.3.0-release-notes.zh-CN.md)。

## 3. 安装到日常 profile

以下命令使用官方 `web` profile。使用其他现有 Web profile 时，将 `web` 替换为你实际使用的名称。

```bash
dsh plugin --profile web add ./dsh-bot-1.3.0.tgz --ignore-scripts --strict-peer-dependencies
dsh web
```

本插件没有安装脚本。无需替换宿主目录、设置产品专用 `DSH_HOME` 或运行额外的 Bot 服务。

在 DSH 侧栏选择 **插件**，确认已安装的 `dsh-bot` 已启用。然后打开 **Bot 空间**；**Bot 工作台** 提供完整管理。首次进入会从 DSH 读取模型目录；模型不存在时，请先在 DSH 中配置模型。

## 4. 创建第一个 Bot

在侧栏打开 **Bot 空间 → 新建 Bot**。填写名称，职责选填，模型默认沿用 DSH 当前有效配置；点击 **提交创建 Bot**。创建只保存 Bot，不会立即发送消息。

在空间左栏选中这个 Bot，再点击 **开始新对话**。中央标题持续显示当前 Bot 的名称、状态和模型，原生输入框上方也显示 **正在与某 Bot 聊天**。多个 Bot 同名时，用稳定 ID 区分。

已有聊天显示在该 Bot 下方；点击聊天的原名称与 ID 继续原历史。选择 Bot 或浏览群不会自动创建会话。空间左栏可以搜索名称或 ID，右栏查看当前 Bot 的任务、身份与记忆；小窗口使用 **会话** 和 **上下文** 打开相应区域，用关闭按钮或 Esc 收起并回到打开它的按钮。

Bot 空间位于 DSH 内的专用面板。**完整工作台** 保留 Bots、任务、记忆、协作、管理五个常用导航；原有卡片的“开始聊天”“继续聊天”和“新建 Bot 会话”入口仍可使用。

当前会话实际挂载的原生工作工具默认可用，实际调用沿用 DSH 权限与审批。Bash 是否可用取决于当前会话的 preset。`dsh_bot` 的 `help.commands` 列出业务管理动作；`tools.list` 或 `help.toolCatalog` 列出当前调用会话的原生工具，详见 [使用手册](guide.zh-CN.md#原生工具与配置边界)。

需要定制时，在完整工作台展开 **更多设置**：工作目录、执行模型、思考程度、回复长度与原生会话配置都在这里。工作目录默认沿用 DSH。执行模型选择“与聊天模型相同”时自动跟随；明确选择某个模型时保持固定，即使两者暂时相同。新建 Bot 默认沿用当前 DSH 的模型与思考设置；两种会话的回复长度可分别设置。远程 DSH 的自定义工作目录应填写远程机器上存在的绝对目录。

工作台操作者可修改 Bot 配置，Bot 也可通过 `bot.update` 管理自己的配置。修改工作目录或 preset 后，为新配置新建会话或任务尝试；已有原生会话的目录固定，带历史的 preset 遵守官方锁定规则。

## 5. 验证一次完整使用流程

1. 创建两个有名字的 Bot。在 **完整工作台 → 记忆** 中分别保存一条事实；回到空间为各 Bot 新建聊天，核对各自身份与记忆。选择旧聊天时应继续原历史。
2. 在当前 Bot 的右栏点击 **新任务**，填写标题、目标和验收条件，点击 **登记任务**，再明确点击 **开始任务**。登记成功表示记录已保存，执行状态随后显示。
3. 长任务运行期间继续聊天，再启动一个短任务。点击 **查看执行会话** 查看原生日志；停止使用当前任务的 **停止任务**。任务验收、调整、接续和归档在 **管理任务** 中完成。
4. 点击 **新建群**，选择已有启用 Bot 和协调者，再点 **提交创建群**。选择这个群并发送消息，核对每个成员的实际回复。默认一轮、12 次请求预算，可在创建时展开“群轮设置”修改。
5. 运行中的群轮可点击 **停止此群轮**；等待状态从停止中变为已停止。停止被接受不表示所有资源已结算。其他群轮、私聊和任务分别管理。
6. 在群的右栏 **发起会议**，填写议题与共同材料，点击 **开始会议**。独立意见阶段只显示收集进度；点击 **下一阶段** 后再揭示和讨论。出现决定后可 **登记行动任务 → 创建行动任务**，之后明确 **开始任务**。
7. 群成员或会议成员需要工具审批、回答问题或确认计划时，在右栏 **原生待处理操作** 选择对应 **审批**、**提问** 或 **计划确认**。先核对 Bot 与群轮／会议阶段，再使用 DSH 原生控件答复。计划窗口显示 **完整原生计划**，可 **同意执行**、**要求修改** 或 **拒绝**；问题使用原生控件答复。关闭空间弹层或按 Esc 只隐藏显示。带原始调用 ID 的请求使用原生“收起问题面板”时仍保留，可通过 **重新打开提问**／**重新打开计划确认** 回到同一个未答请求；无 ID 请求的原生 **放弃整组问题** 会取消请求，不能重开。尚未揭示的会议意见始终封存。

需要移除 Bot 时，进入 **完整工作台 → Bots → 删除 → 确认删除**。这是保留原身份的可恢复删除：原会话、记忆、任务、执行记录和操作 ID 仍保存。有活动或未知工作、未完成群／会议、原生待处理输入或待投递结果时会阻止删除。先停止确切工作并等待结算，未知状态先查回。通过 **已删除的 Bot → 恢复** 找回原 Bot，随后在 **状态管理 → 启用** 恢复使用。

跨 Bot 默认只读；需要更大共享范围或控制权限时，在 **完整工作台 → 管理 → 共享与授权** 明确设置，保存后持续有效且可撤销。完整任务流程、会议和共享说明见 [使用手册](guide.zh-CN.md)。

## 6. 升级、禁用与卸载

关闭插件开关会请求停止插件管理的运行并移除空间与工作台入口，资源是否结算以真实证据为准；原生历史和长期记忆仍保存。重新启用后读取原账本，并重新绑定仍由 DSH 管理的既有 Bot 联络会话；活动不明的资源和未明确结算的工作保留未知状态，不自动重放。

官方 rc.2 的插件管理器升级方式是先卸载，再安装新版。先让工作结算或明确停止，并使用 DSH 自己的备份方式保存现有 profile 数据，然后：

```bash
dsh plugin --profile web remove dsh-bot --config.ignore-scripts=true
dsh plugin --profile web add ./dsh-bot-1.3.0.tgz --ignore-scripts --strict-peer-dependencies
```

重新启动或启用插件后，Bot ID、记忆、会话和任务读取原持久数据。卸载只移除插件依赖与入口；手动删除 DSH 存储不属于卸载步骤。

从 v1.0.0、v1.0.1、v1.0.2、v1.1.0、v1.1.1、v1.1.2、v1.1.3 候选、v1.1.4 或 v1.2.0 升级到 v1.3.0 时，请先备份原 DSH profile 并完全退出进程，再执行上述命令，启动同一 profile 并刷新浏览器。完整工作台标题下方应同时显示 **插件 1.3.0 / 服务 1.3.0**。原 Bot ID、记忆、会话、任务和待查回的原始操作及持久回执保留。界面与运行服务不同版时，新写入会被明确阻止并给出重启／刷新提示。

v1.1.3 未发布稳定 Release；曾手动安装该候选的 profile 也按以上步骤升级，保留原数据和操作身份。

浏览器中已有的原始操作 ID 继续保留。在“待查回的原始操作”先点 **查回原始操作**：它只读持久回执，不执行任务，也不调用模型。找到回执后刷新原对象；没有回执时保留“未确认”。**用原 ID 接续**是单独的显式提交，并先检查原回执；已提交操作不会重复创建。不要修改原 ID 的内容或将旧操作改用于新动作。

已拒绝或不再接续的请求可以 **保留并收起**，原 ID 与完整请求仍在折叠的历史中可查。目录刷新不会清除刷新期间新产生的待查回记录或已保留历史；取消页面读取也不会丢弃已接受写入的原始回执。目录中暂时消失的模型或 preset 显示“当前不可用”，已保存和当前草稿选择都保留；选择替代项或默认配置必须由你明确操作。

## 7. 故障处理

| 现象 | 处理 |
| --- | --- |
| `pnpm was not found` | 安装 `pnpm@11.19.0`，确认启动 DSH 的环境可以执行 `pnpm --version`。 |
| Bot 空间／工作台没有出现 | 在原有侧栏“插件”中确认 `dsh-bot` 启用；检查官方 DSH 版本和该 profile 的运行诊断。 |
| 模型列表为空／无法回答 | 先确认普通 DSH 对话正常，再检查该 Bot 的模型配置和 DSH 凭据。 |
| `model_drift` | Bot 会话使用 Bot 配置的模型。回工作台调整联络／执行模型，再发起新轮或新尝试。 |
| `revision_conflict` | 另一页面已经修改对象。当前 Bot 配置草稿保留；点击“重新载入最新配置”后按新版本修改。 |
| `plugin_version_mismatch`／首次创建出现 `invalid_input` | 核对工作台的插件／服务版本，按升级步骤装同一新版、完全重启 DSH 并刷新页面；保留原操作 ID，先只读查回。配置验证失败时新版会注明提交被拒及未写入。 |
| 群回复没有继续 | 查看该群轮的缺席原因、预算、停止状态与右栏“原生待处理操作”。审批、提问与计划属于具体 Bot；带原始调用 ID 的未答请求可收起再重开。无 ID 请求的原生“放弃整组问题”会取消，空间弹层关闭则只隐藏显示。 |
| 提问显示“已继续工作，仍可回答” | 原群轮／会议阶段仍有效且工作尚未结算时，可通过原请求答复；连接中请等待原生问答就绪。已经答复、取消、结算或失效的旧请求不会复活。 |
| 模型目录变化 | 原模型会显示“当前不可用”；显式选择替代模型后保存，插件不会在改名时自动换模型。 |
| 会议已取消，工作仍未结算 | 取消先关闭会议流程，原通道资源可能仍待停止或确认。尚未揭示的意见继续封存；查看“管理会议与通道”，已登记的行动任务单独停止。 |
| 任务、共享、群或会议草稿冲突 | 原草稿保留在开始编辑时的版本／会议世代。先阅读最新内容，再点对应“重新载入最新…”重新编辑；旧共享草稿不能恢复已撤销的共享。 |
| `access_denied` | 在“共享与授权”核对接收 Bot、共享上限、具体会话／任务范围和有效权限。 |
| Bot 找不到 Bash／把业务动作当作全部工具 | 让 Bot 调用 `tools.list` 或读取 `help.toolCatalog`，核对当前会话实际挂载的工具及限制；需要其他 preset 时修改自身配置或在 `session.create` 指定新会话配置。 |
| 删除 Bot 被阻止 | 先处理活动任务、原生回复和待处理输入，查回 `UNKNOWN` 工作及待投递结果；停止被接受后仍须等待真实结算。 |
| 恢复 Bot 后“开始聊天”不可用 | 恢复保留原 ID 并回到暂停状态；在“状态管理”中单独点击“启用”。 |
| 群轮显示停止中／停止已接受，但还未结算 | 等待模型、工具、作业、终端或子工作的真实终止证据；占用会在结算后释放。 |
| `browser_storage`／浏览器存储提示 | 原请求完整保存失败时不会发送新写入；恢复存储后用原 ID 接续。只读查回仍可使用；已提交回执的清理失败不会改变操作成功状态。 |
| 状态为 `UNKNOWN`／“未知” | 使用“结果与投递”及待查回的原始操作查询实际日志。不要重新登记替代任务来掩盖未知状态。 |
| 同一 profile 写入者冲突 | 关闭该 profile 的重复宿主进程，再正常启动；多个浏览器页面可以连接同一个宿主。 |
| 存储损坏／版本不兼容 | 保留原 profile 和日志，读取诊断；插件会拒绝覆盖坏数据。 |

[旧独立软件版及其安装器已作废](history/standalone-void.md)。它们不作为本插件的安装步骤或依赖。

### schema 2 存储与升级

从 v1.0.0／v1.0.1／v1.0.2 升级时，schema 2 在原 profile 的同一记录原子迁移，保留原始身份、回执和校验过的 schema 1 备份。旧 Bot 与旧持续授权的新增资料范围为关闭。升级后不要直接在同一份 schema 2 存储上降级旧插件；回退需使用升级前独立备份和对应旧插件包。迁移失败或未来格式不会覆盖原记录。

从 v1.1.0／v1.1.1／v1.1.2／v1.1.3 候选／v1.1.4 或 v1.2.0 升级到 v1.3.0 沿用 schema 2 与协议 2，不重新迁移或创建替代对象；原资料、安排、通知和已有迁移备份继续保留。宿主仍为未修改的官方 DSH 0.2.0-rc.2。
