# Thin v1 installer design

The authorized goal is a first installation using a trusted thin bundle and ordinary Node/npm, without Git, old dependencies, old Homes or credentials. The bundle carries reviewed product bytes, helper code, the selected Host overlay and its exact external registry/source materials, notices and the official SDK lock. It carries no complete official SDK installation. SDK packages are fetched directly from the public registry during first installation; the resulting complete graph is a private local runtime, with public-release qualification still false.

## Contract and flow

`installV1({bundleDirectory, descriptorPath, expectedDescriptorSha256, outputDirectory, npmCliPath, npmTimeoutMs=120000})` requires canonical absolute paths and an absent output outside the input bundle and selected npm entry. The CLI spells these as `--bundle`, `--descriptor`, `--descriptor-sha256`, `--output`, `--npm-cli`, and optional `--npm-timeout-ms`. Timeout is an integer from 1000 through 300000 milliseconds.

The caller pins the descriptor independently. Its format is `1`, classification `DSH_BOT_V1_THIN_INSTALL_BUNDLE`, `publicReleaseQualified:false` and `runtime:{nodeVersion:'24.19.0'}`. Actual Node must be exactly 24.19.0 and the actual platform/architecture must be Linux/x64 or macOS/arm64, checked before artifact bytes, output creation or npm. `files` contains unique relative canonical records `{path, bytes, sha256, mode, target}`; `target` is `common` or a target ID. `targets` contains Linux/x64 and/or macOS/arm64 entries `{id, platform, arch, overlayDirectory, sourceIdentity, sourceLock, sourcePacket, buildRecipe}`. IDs are `linux-x64` and `darwin-arm64`. Only common and the actual host's target files are read or copied.

The descriptor declares `officialSdk:{lock,cliVersion:'0.2.0-rc.2'}`, `product:{manifest,archive,buildId}`, and `registry:{directory,receipts}`. `licenses` has `public`, `native`, `muslCopyright` and `muslSourceNotices` file paths. `tools` pins the fixed layout `scripts/install-v1.mjs`, `scripts/assemble-distribution-runtime.mjs`, `scripts/install-bot-gui-profile.mjs`, `scripts/package-snapshot.mjs`, and `tools/runtime-export/export.mjs`, preserving reviewed relative imports. Every referenced file is inventoried for the selected target; all files beneath the selected overlay directory are also inventoried. Core count is 74 and external snapshot count is 28. Source packets/recipes are retained as materials and are never executed by the installer.

Before creating output, selected files are checked through `O_NOFOLLOW` descriptors, including canonical identity, hash, size and mode with before/after descriptor/path stats. Inputs are checked again when copied into an exclusive `materials` view. The descriptor and host npm entry retain their first safely read hash/size/mode identity through the final reread as well. Secret/configuration paths, traversal, symbolic aliases and nested `node_modules` inputs are refused. Input changes cause a fixed-category refusal. The bundle is copied only by inventory, without recursively walking unrelated files or reading unselected targets.

The fresh output contains `materials`, `sdk`, `npm-home`, `npm-cache`, `npm-tmp`, empty user/global npm configs, a verified unpacked `product`, consumer-produced `runtime`, and fresh `profile`/`work`. The npm child executes safely captured CommonJS npm-entry bytes through current Node, retaining the canonical host npm filename for its public module resolution. Node never rereads the caller-controlled npm-entry path. It runs `ci --ignore-scripts --no-audit --no-fund`, strict TLS, HTTPS registry, a fresh empty cache and explicit empty configs. Only PATH, LANG, standard proxy and public CA settings are inherited; public CA files are read safely and copied into private certificate views before delegated Node reads. HOME and temporary/config locations point into the owned output. Provider keys, NODE_OPTIONS, NPM_CONFIG settings and previous Home/config paths are not inherited. Output is not forwarded from npm; timeout/error categories are fixed. The host's public npm implementation and Node installation remain explicit prerequisites, not thin artifact payload.

The child PID/group is captured once. After timeout, TERM and a KILL request after 250ms require an unchanged PID, live original leader and unchanged output ownership; no positive-PID fallback or signal to another group is used. A stop-confirmation phase lasts at most 750ms, whether triggered by timeout, error or leader exit. Both observed leader exit and an absent original process group are required for acceptance or ordinary cleanup. Group presence/query denial, changed/unavailable process identity, or changed output ownership yields `SDK_INSTALL_STOP_UNKNOWN`; the output is preserved with the captured child and original directory identity. The child handle is unreferenced, and the CLI exits1 after its bounded 100ms diagnostic flush even if a writer remains. Leader exit does not cancel confirmation or imply the whole group stopped. The installer conservatively preserves unconfirmed groups after the original leader exits, since that leader no longer anchors a destructive signal's ownership.

The reviewed package decoder checks product tar members and closure before extraction. Its tarball hash/file index must match the supplied pinned manifest; original source root/head/tree are preserved. The qualified consumer assembles all 74 peers with the exact 28 registry snapshots and pinned official lock. The GUI helper receives `packageSourceMode:'verified-export'` and exact packed manifest SHA/buildId, so installation requires no `.git`. The installer never starts the CLI, native code or a model. Existing GUI startup defaults model requests to false; only a later actual `--enable-model-requests` startup flag enables that gate.

The result and `installation-manifest.json` record input/receipt pins, original product identity, fresh paths and a manual startup argv. Credential information is only the reference `DEEPSEEK_API_KEY`; no key value or auth token is read, stored or printed. Failures remove only the output whose retained inode/device and private 0700 mode still match. Changed/unknown ownership or mode preserves the directory and reports a bounded cleanup category. This does not promise general isolation from hostile concurrent writers with the same OS identity.

## Verification and limits

Real owned filesystem/child fixtures exercise pin, path, platform, protected-name, tar, source drift, fresh-cache/config/env, timeout and cleanup boundaries. The assembly integration fixture uses the actual reviewed consumer/exporter and actual GUI helpers with a coherent 74/28 synthetic graph. There are no network, model, native or real runtime operations in this feature's initial test phase. Final coherent product/M1 pins and independent consumer qualification are prerequisites for a real thin install. An external fresh OS/container test and public license/rights/source-offer qualification remain separate gates.
