## 本版调整

- 会话列表更新后保留诊断面板的展开状态和所选原操作。更换选择或关闭预览后，迟到回复仍不能恢复旧预览或复制入口。
- 增加真实已安装 GUI 回归：延迟投递一份真实、非空的 session.list 回复，选择原操作并展开诊断后释放列表，验证选择与展开状态保留。原有 120 项具名检查继续保留，本版要求 **121 项**全部通过。
- 安装验收按真实 Bot 稳定身份选择与操作对象，不依赖随机 UUID 的排序；保留原 Bot ID、原生日志、原消息与操作回执。
- 继续保留独立记忆、当前来源权限、冷普通会话管理、任务调整的原尝试树停止、子工作原生配置、暂停定时结算、完整模型参数恢复及既有工作台修复。已有只读共享回边按实际权限核验；真正来源循环、撤权和封存会议来源继续拒绝。

## 合并后验收发现与继续修复

[PR #9](https://github.com/86cloudyun-afk/dsh-bot/pull/9) 的最新提交与 PR 合成提交均通过双平台完整验收，但合并后的 [main CI](https://github.com/86cloudyun-afk/dsh-bot/actions/runs/38038520584) 未通过：macOS 的 GUI 与七升级通过，Linux 的 GUI 进程退出 1，只有四张阶段截图，没有最终 JSON 报告。因此当时没有创建 v1.1.4 标签或稳定 Release；之前的通过结果不能代替这一轮失败。

独立复现确认了两处验收脚本缺口：已移除的浏览器网络拦截仍可能有未完成回调，页面刷新后履行原回复会发生异步错误；官方 SDK 的失败处理会直接退出，绕过原有异常监视报告。两项均使用受控子进程或真实 Chromium 复现，未调用外部模型。原 CI 的具体异常仍未知，不能从截图推定。继续修复必须保留全部原检查、原响应、原操作 ID 与回执，并重新完成同提交验收和最终平台门槛。

本轮进一步收口同类路径：路由错误先结算真实请求，再通过等待中的清理流程传播；已经取回响应的原请求不能因回调出错而再次投递。记忆搜索立即观察原 RPC，并在释放原回复后等待路由和 RPC 收尾；导出同时观察原 RPC 与下载等待。异常退出只保留本轮报告，旧目录中的失败记录不能冒用本轮身份、阶段、检查或请求数；未证实的错误和清理结果仍保持未知。首轮新增真实 Chromium 六项回归纳入两平台 CI，现有 121 项 GUI 与八份报告门槛保持不变。

首轮修复在 `7a384408` 上完成完整回归 **753/753**、真实 Chromium 定向回归 **6/6**、完整 GUI 与七升级；对应远端分支和 PR 验收也通过。随后 PR 复审发现三处需要继续修复的失败边界：记忆搜索的原请求失败后仍等待响应超时；清理中的中间报告被当成终态保存；升级的父、子进程未安装退出报告观察器。真实已安装页面证实第一项原流程延迟约 30 秒后超时，未证实永久等待，也不能据此认定旧 main CI 的具体原因。

最终修复按实际 Request 身份观察响应、失败与页面关闭，结算交互错误、取消及超时，并清理全部监听器；原成功断言和回执继续保留。异常退出只保留本轮真正终态报告；初始化错误保留当前内存中的脱敏原因。升级的父、子进程均安装不改变 SDK 退出语义的观察器；子报告完整替换父阶段数据，清理父资源单独记录，不把子进程的未知／未完成清理改为完成，不借用父阶段请求计数，也不借用旧目录的报告。新增实际 SDK 三项回归覆盖两种入口与真实父→子升级失败。

第三轮完整回归 **771/771**、真实 Chromium 路由与 RPC 定向回归 **14/14**、真实 SDK 升级失败回归 **3/3**、静态与分发校验均通过。在最终干净冻结提交上重新完成完整 GUI 与七升级，八份新报告经严格门槛及独立复核全部通过；之前的报告只保留原提交的证据，不改标为本轮结果。

## 浏览器测试初始化与取消清理的继续复审

第三轮的 [分支 CI](https://github.com/86cloudyun-afk/dsh-bot/actions/runs/38044025514) 两平台通过；对应 [PR CI](https://github.com/86cloudyun-afk/dsh-bot/actions/runs/38044028281) 的 Linux 首项路由测试触发超时取消，其余 13 项通过，安装／GUI／升级尚未运行；macOS 完整验收通过。失败保留为失败，分支通过不代替 PR 失败。原超时具体阶段仍未知。

随后用真实 Chromium 和真实延迟 HTTP 导航复现同类缺口：初始化放在较短的路由验证时间内，取消后函数末尾的清理不能保证及时执行。修复将初始化 30 秒与原路由验证 10 秒分开；提前登记资源所有权，保留实际迟到分配、持有回复取消及准备阶段请求失败的原错误，在下一项测试前结算并关闭资源。原六项用例、36 处断言与路由时间限制全部保留。

另一处真实复现确认：浏览器启动失败时，RPC 测试已报错，但 HTTP 测试服务器仍监听、进程未退出。清理现在在启动前注册，覆盖启动失败及迟到浏览器；新增永久回归使用实际测试入口检查原报错、自然退出、服务器关闭事件与端口撤销。启动等待和已知失败后的退出等待分别计时。原八项 RPC 用例与其失败请求时间限制保留。

本轮只调整两份浏览器测试文件，原生插件、安装验收入口、工作流和冻结包与第三轮逐字节一致。最终浏览器定向 **15/15**，失败、取消、跳过与待办均为 0：原路由六项、原 RPC 八项和新增启动失败一项。五项路由真实场景，以及启动失败、真实迟到浏览器和延迟启动的证据均完成独立复核，开放 **C=0／I=0／M=0**。静态与分发校验通过。两个测试文件的冻结实现归属 [22c6f97a9a162412130421acfd76d09fd7558f70](https://github.com/86cloudyun-afk/dsh-bot/commit/22c6f97a9a162412130421acfd76d09fd7558f70)，最终回归使用的文件字节与该提交一致。最新 PR、main、标签必须分别完成实际完整 CI 后发布；第三轮本地报告仍绑定原冻结提交，不改标为新提交。
