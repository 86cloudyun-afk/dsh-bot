## 本版调整

- 会话列表更新后保留诊断面板的展开状态和所选原操作。更换选择或关闭预览后，迟到回复仍不能恢复旧预览或复制入口。
- 增加真实已安装 GUI 回归：延迟投递一份真实、非空的 session.list 回复，选择原操作并展开诊断后释放列表，验证选择与展开状态保留。原有 120 项具名检查继续保留，本版要求 **121 项**全部通过。
- 安装验收按真实 Bot 稳定身份选择与操作对象，不依赖随机 UUID 的排序；保留原 Bot ID、原生日志、原消息与操作回执。
- 继续保留独立记忆、当前来源权限、冷普通会话管理、任务调整的原尝试树停止、子工作原生配置、暂停定时结算、完整模型参数恢复及既有工作台修复。已有只读共享回边按实际权限核验；真正来源循环、撤权和封存会议来源继续拒绝。

## 合并后验收发现与继续修复

[PR #9](https://github.com/86cloudyun-afk/dsh-bot/pull/9) 的最新提交与 PR 合成提交均通过双平台完整验收，但合并后的 [main CI](https://github.com/86cloudyun-afk/dsh-bot/actions/runs/38038520584) 未通过：macOS 的 GUI 与七升级通过，Linux 的 GUI 进程退出 1，只有四张阶段截图，没有最终 JSON 报告。因此当时没有创建 v1.1.4 标签或稳定 Release；之前的通过结果不能代替这一轮失败。

独立复现确认了两处验收脚本缺口：已移除的浏览器网络拦截仍可能有未完成回调，页面刷新后履行原回复会发生异步错误；官方 SDK 的失败处理会直接退出，绕过原有异常监视报告。两项均使用受控子进程或真实 Chromium 复现，未调用外部模型。原 CI 的具体异常仍未知，不能从截图推定。继续修复必须保留全部原检查、原响应、原操作 ID 与回执，并重新完成同提交验收和最终平台门槛。

本轮进一步收口同类路径：路由错误先结算真实请求，再通过等待中的清理流程传播；已经取回响应的原请求不能因回调出错而再次投递。记忆搜索立即观察原 RPC，并在释放原回复后等待路由和 RPC 收尾；导出同时观察原 RPC 与下载等待。异常退出只保留本轮报告，旧目录中的失败记录不能冒用本轮身份、阶段、检查或请求数；未证实的错误和清理结果仍保持未知。新增真实 Chromium 六项回归纳入两平台 CI，现有 121 项 GUI 与八份报告门槛保持不变。

本轮完整回归 **753/753**、真实 Chromium 定向回归 **6/6**、静态与分发校验均通过。随后在本轮干净冻结提交上重新完成完整 GUI 与七升级，八份新报告经严格门槛及独立复核全部通过；旧报告只保留其原提交的证据，不改标为本轮结果。
