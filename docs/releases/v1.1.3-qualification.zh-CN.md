## 修复后的行为

- 自己的记忆写入及相互只读查阅不会使 Bot 联络会话失去可读性。真实来源、封存会议意见和当前撤销权限仍逐项核验。
- 删除 Bot 前检查冷日志中的未结束回复和待处理输入，检查期间封住新准入；保留原 ID、删除回执及可恢复历史。
- 接受实际任务调整时，同一提交保存旧尝试及子工作森林的停止意图。随后撤销调用者授权或关闭调用会话，不阻断已接受的停止；真实资源结算前继续占槽，旧调整不停止新尝试。
- 普通会话在官方输入准备完成、原消息真正入队前重新检查当前来源权限；恢复已有冷普通会话使用官方解析接口，不将它登记为 Bot 工作。群回复发布前也重新检查来源权限。拒绝发布保留原生日志和原始操作记录；恢复授权后需明确接续或开始新工作，不自动重放。
- 冷普通会话可在原控制授权下恢复并配置；它继续由 DSH 管理。停用插件后保留已接受的会话模型设置；重启并启用插件后，即使此前未发送消息，也恢复已确认的完整参数。随后在原生界面选择的新模型仍生效，全局默认不会被插件配置改写。
- Bot 直接登记会议行动也保存会议权限依赖；人类独立编写和分配任务的语义保留。取消会议和撤销成员权限分别处理。
- 子工作使用准入时的真实目录、preset 和有效父权限；创建途中父会话改变权限，不改写已捕获的子权限。读取活动会话页先保存真实缓冲日志，再检查当前权限。
- 暂停／取消定时安排阻止未来准入，已经接受的任务继续按原身份完成结算。
- 历史记忆来源不再受任意四层截断，固定记忆也检查原有容量。严格 JSON 处理保留原字节规则与指纹；超出官方编码能力的内容须明确拒绝，原数据及回执保持完整。
- 刷新进行中请求强制刷新仍会重新载入目录；成功重试资料搜索清除该查询自己的旧错误。未改动的默认全部只读共享保留未来 Bot；安排编辑固定原负责人，新建时仍可选择。

## 范围

使用官方 SDK 的真实会话、日志、消息、资源和持久回执复现原生问题，使用实际客户端行为回归及已安装插件的真实 Chromium／认证 RPC 验证界面。提供者由测试控制，外部真实模型请求为 0；不访问或升级用户现有 Host。

从 v1.0.0、v1.0.1、v1.0.2、v1.1.0、v1.1.1、v1.1.2 的固定历史包升级，必须关闭旧进程并在新进程核对原身份、回执、记忆、资料、安排、通知、结果、投递、原生日志及备份。具名完整报告同时绑定同一源码提交和冻结包，缺项、脏源码、退出未清理及来源不符均不通过。

当前包只分发 MIT 原生插件源码及中文操作说明，不重新分发 DSH 依赖。旧独立软件继续作废，PR #1 关闭未合并；保留的旧分支、历史和资产不参与当前交付，不认证历史修改 Host 的全部许可。Bot 名称由用户指定；UNKNOWN 和原始操作 ID 保留，不以替代任务或重复模型请求掩盖不确定性。
