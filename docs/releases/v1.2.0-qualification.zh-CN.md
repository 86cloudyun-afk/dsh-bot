# DSH Bot v1.2.0 · 聊天接续、资料检索与恢复可靠性

本版直接安装到未修改的官方 **DSH 0.2.0-rc.2**，保持 **schema 2／客户端协议 2**。本地完整回归、已安装原生 GUI 和八条升级路径已通过；最终 PR、main 和标签分别完成双平台验收后发布，实际链接由 [本版 Release](https://github.com/86cloudyun-afk/dsh-bot/releases/tag/v1.2.0) 记录。

## 本版升级

- Bot 卡片增加“继续聊天”，按稳定 Bot ID 列出已有原生聊天，显示名称与会话 ID，直接打开所选原会话。页面切换、归档或删除后的迟到回复不能打开旧选择。
- 浏览器完整保存原请求后再发送修改。存储失败保留草稿并明确请求未发出；已收到确定回执后的清理失败不会把已完成操作改称未知。保留原 ID 的只读查回不依赖新的存储写入。
- 操作提交后获取新的快照，避免把提交前正在读取的结果当成最新数据；刷新成功只清除其自身的旧连接错误。
- 资料搜索支持跨相邻 800 码点块的中日韩词、英文词和短语，仍返回原 chunkId、哈希、原文偏移与行号；权限、稳定排序和真实引用保持。
- 实际消费群回复时传递真实来源依赖。原来源撤权后，后续会话、资料与记忆读取继续检查权限。已有缺失来源的历史记录保留，不根据猜测回填。
- 停止父工作时同步标记真正持槽的子尝试及其当前任务，仍等待实际结算后释放资源。编辑未改变规则的单次提醒保留原触发时间，暂停后恢复只产生一次迟到通知。
- 修复已有安排环境中编辑后重复卡片的问题：列表卡片与编辑器使用不同的 React key，原安排 ID、版本、排序和回执保持。

## 失败记录与修复

首轮完整 GUI 发现资料正文选择器同时匹配多个区域，修复为精确的正文标题与关闭入口；保留原字节、哈希和引用断言。随后完整 GUI 在提醒编辑后发现两个启用按钮。用已有三个安排的官方环境稳定复现：存储中四条唯一记录，页面却残留六张卡片；真实组件 key 确认列表卡片和编辑器发生冲突。只给编辑器增加独立 key 前缀后，相同环境为四条记录、四张卡片、目标一张，原 CAS 版本及一次通知通过。没有选择第一个重复按钮或删除原检查。

早期本地及远端失败保留原源码、包哈希与结果；远端脱敏错误不能证明的具体原因仍保持未知。最终本地验收使用新包和干净冻结源码重新运行全部九条路径。正式发布须另外通过最新 PR、合并后的 main、标签实际 CI：Linux／macOS × Node 22／24 的 855 项回归，两平台真实 Chromium **15/15**、官方 SDK **3/3**、GUI **128/128** 和八升级各 **7/7**。

## 交付边界

具名多 Bot、独立记忆、持续聊天、任务、群会议、知识和定时能力延续原规格；当前会话原生工具默认可用，沿用 DSH 审批，跨 Bot 授权持续有效且可撤销。15 工作槽、一级子工作、停止与结算分开记录，以及 UNKNOWN 不自动重放的规则保持。

验证使用受控提供者和隔离 profile，不访问或升级用户现有 Host。MIT 插件包不重新分发 DSH／Host／SDK 或依赖。旧独立软件继续作废，PR #1 关闭未合并，历史分支和归档保留为不受支持的历史材料。
