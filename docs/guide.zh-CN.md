# 使用 DSH Bot

日常创建 Bot 只需填写名称，职责选填、模型默认沿用 DSH。当前会话已挂载的原生工作工具默认可用，无需手动填写工具名。Bot 卡片的“开始聊天”直接进入该 Bot 的新会话；个别模型和目录参数在“更多设置”。

## Bot、会话与长期记忆

在工作台先创建并命名 Bot。新建 Bot 会话只选择已经创建的 Bot；一个 Bot 可以拥有多个会话，每个会话保留自己的聊天历史。

首条消息发送前，原生输入框上方即显示 **正在与某 Bot 聊天**。当前会话的原生标题栏也持续显示 Bot 身份；工作会话与协作会话注明用途。两个 Bot 同名时，身份标识通过稳定 ID 区分。暂停 Bot 的聊天会话、已删除 Bot 的历史会话会注明状态，点击身份标识可返回工作台。

同一 Bot 的身份、长期记忆和未完成任务会自动带入新会话。需要细节时，可以让 Bot 查阅自己的其他会话。记忆按 Bot 分别保存，其他 Bot 的只读访问不会合并或改写它的记忆。保存自身记忆或 Bot 之间互相只读后，仍可继续正常聊天；涉及其他来源的上下文会重新检查当前权限。遗忘长期记忆保留原始会话日志和来源引用。

在 **Bots → 编辑** 修改职责和模型。需要单独配置任务模型时展开“更多设置”：默认“与聊天模型相同”会自动跟随；明确选定的模型会保持固定。已有配置不会仅因两个模型当前相同而自动改成跟随。另一页面同时修改时，当前草稿保留，保存会检查原版本；点击 **重新载入最新配置** 后再修改。

## 删除与恢复 Bot

在 Bot 卡片点击 **删除**，阅读确认框后再点击 **确认删除**。插件保存可恢复的删除标记，并从常用 Bot 列表和新建聊天选择中移除该 Bot；原 Bot ID、会话历史、长期记忆、任务、执行记录及原始操作 ID 和回执保留。

活动任务、未结算或 `UNKNOWN` 工作、未完成群／会议流程、正在进行的原生回复、inbox 中待处理的输入，以及 outbox 中待投递或入队状态不明的消息都会阻止删除。DSH 异常退出后，即使会话尚未加载 Agent，删除也会检查原生日志中持久的待处理输入和未结束回复；日志无法确认结算时仍会拒绝。删除操作不会代替停止或清空队列；先处理或停止确切工作并等待真实结算，未知状态先查回原始证据。

在 **Bots → 已删除的 Bot → 恢复** 中恢复同一 Bot。恢复后状态为 **暂停**，需要再通过卡片的 **状态管理 → 启用** 明确启用，之后才能开始新聊天或任务。删除与恢复均由人类操作，控制授权不授予 Bot 这些动作。

## 原生工具与配置边界

Bot 默认可以使用当前原生会话已挂载的工作工具，实际执行继续遵守 DSH 的权限、审批、沙箱和会话状态。Bash 是独立原生工具；preset 挂载它时可用，无需通过 `dsh_bot` 另行授予。不同 preset 的工具范围可能不同。

`dsh_bot` 的 `help.commands` 只列插件业务管理动作。让 Bot 调用 `tools.list` 或读取 `help.toolCatalog`，可查看**当前调用会话**实际挂载的原生工具 schema、执行路径和限制；它们是只读查询，不授予新工具。`native_guarded` 表示工具已挂载、执行仍受原生检查；`plugin_blocked` 表示插件阻止该入口；`managed_work_required` 提示通过 `task.create/task.start` 登记和启动工作。人类查看的全运行时 `inventory` 可以包含不同 preset 的工具，不代表某个 Bot 都能调用。

Bot 可通过 `bot.update` 修改自己的名称、职责、模型、默认工作目录、preset 和状态，也可通过会话管理动作查询、冷读、发送、停止、归档、恢复、配置和接续自己的会话。其他 Bot 的控制授权不包含修改其身份配置。创建／删除／恢复 Bot、共享与授权及会议阶段由工作台操作者管理。

`session.create` 可指定新会话名称、模型、preset 和工作目录；`session.configure` 可管理已结算联络会话的名称、模型与官方仍允许修改的 preset。原生回复、排队或资源未结算时，配置操作会拒绝。已有聊天的 preset 被官方锁定、工作目录固定；`session.fork` 按真实原生日志边界接续新会话，可选择名称、模型和新目录，并继承原有效 preset。不同 preset 使用新建会话；原历史与身份不被改写。执行／会议通道的在途绑定通过对应任务或会议流程管理。

原生 `plugin_manager` 管理整个 DSH profile，仍受工作域边界限制；直接 subagent 派发需要进入受管任务准入，保存真实槽位、身份和停止证据。

## 聊天与后台工作

Bot 的联络会话和工作执行会话分开。把耗时工作交给任务后，仍可继续聊新话题、询问进度、派发短任务、调整目标或要求停止。可以直接用自然语言委派，也可以在工作台操作。

每个 Bot 的父工作、一级子工作和未结算未知工作共用 15 个工作槽。工作 Agent 先经 `task.create/task.start` 准入，再使用真实原生 subagent 执行；直接委派入口不能绕过任务登记和槽位限制。新子工作按已确认的工作目录与 preset 创建，并保留准入时捕获的父级原生权限与审批；创建等待期间父级配置改变不会改写这次委派。子工作只允许一级；原生子 Agent 控制仍检查实际调用者与父子关系，停止或接续任务使用 `task.stop/task.start`。后台工作不会占用独立联络通道。模型服务自身的限流和响应等待仍会显示实际状态。

### 一个任务的完整流程

1. **登记任务**：选择负责人、填写标题和目标。需要指定验收条件或接收会话时，展开“验收与结果接收”。
2. **开始／接续**：启动一个真实工作尝试；**查看执行** 打开 DSH 原生日志。一级子工作可以选择同 Bot 的当前父工作。
3. **调整目标**：展开“调整与接续”。实际改变任务定义时，定义变更和确切旧尝试树的停止意图共同保存，封住旧尝试并请求停止，待其结算后按新目标接续。已接受的调整即使随后断线、调用者离开或控制授权撤销，也继续处理这棵原尝试树。内容和负责人均未改变时保留原任务版本、验收与正在运行的尝试，不发出停止。任务 ID 保留，新尝试有自己的世代；重查旧调整不会停止后来启动的尝试。
4. **停止本次尝试**：停止按钮针对当次尝试。显示“停止已接受”后仍等待真实资源结算；旧停止不会取消后续尝试。
5. **记录验收**：结果结算后展开“验收结果”。结果返回与通过验收分别保存。填写真实证据，选择通过、待定或不通过。
6. **归档／恢复**：已结算任务可归档并恢复。身份、结果和原始日志保留。

结果可回到 Bot 联络会话或普通 DSH 会话。消息和结果在实际原生准入前重新检查来源权限；请求接受后来源被撤销时，尚未准入的内容会被阻止。遇到断线或丢回执，“结果与投递”和“待查回的原始操作”保留原身份用于查回。未知工作不会自动重放或提前释放槽位。并发查回或迟到的投递应答失败不会抹掉已保存且匹配原会话、消息与原生日志序号的接受证据；没有确切证据时仍保留未知。

待查回记录的 **查回原始操作** 只读原回执；未找到回执时仍显示未确认。需要接续时单独点击 **用原 ID 接续**，插件先检查相同请求的回执。超过 30 条待查回操作时停止接纳新提交，保留全部旧 ID。

对于已经拒绝或不再接续的请求，点击 **保留并收起**，完整原始请求及 ID 保存到折叠的“保留的原始操作”，仍可只读查回。它只腾出浏览器待查回位置，不停止任务、不改变宿主未知状态，也不删除原始记录。手动刷新会重新读取模型／preset 目录，即使后台状态刷新正在进行；期间产生的新待查回记录与保留历史会合并保留。离开页面或取消读取不丢弃已接受写入的原始操作 ID 和回执。

任务调整、验收、共享范围、群成员及会议草稿保留开始编辑时的版本或会议世代。其他页面修改后，保存不会静默覆盖最新内容；使用对应 **重新载入最新…** 按钮阅读并重新编辑。旧共享草稿不能恢复已经撤销的共享；旧会议行动草稿不能自动挂到新会议决定。

## 共享与授权

跨 Bot 默认只读共享本插件管理的会话、任务、记忆与资料。旧版本升级的 Bot 资料范围默认为关闭，需明确启用。普通 DSH 会话需要人类明确授权给 Bot。

在 **管理 → 共享与授权** 中选择接收 Bot，设置会话、任务、记忆、资料的共享范围，或关闭共享。默认“所有 Bot”范围包括以后创建的 Bot；未修改接收方时保存仍保留该范围，即使当前没有其他 Bot。明确改为具体 Bot 后，只保留所选接收方，后来新增 Bot 不自动加入。共享范围是访问上限；持续授权可以在该上限内授予只读或控制权限。控制会话和任务时可以限定具体 ID；权限保存后持续有效，可撤销或降级。

控制权限不包含修改另一个 Bot 的身份、模型、记忆或共享策略。撤销后，新的操作、排队动作和结果发布重新检查当前权限。已经执行的外部动作保留真实历史。

## 内部群与会议

在 **协作 → 内部群** 中选多个 Bot 和协调者，填写群名创建群。轮数与请求预算沿用默认值；需要时展开“群设置”调整。发送消息后，每个成员使用自己的身份和模型产生实际答复。

在群卡片展开“开会”，填入议题和共同材料，点击 **发起会议**。同一群可以同时召开不同议题的会议；各会议的材料、世代和预算分别保存。

会议按以下阶段进行：

1. **独立意见**：各 Bot 先分别形成意见；揭示前不能读取其他参与者的封存意见。
2. **揭示并讨论**：明确进入讨论，成员结合共同材料和已揭示意见发言。
3. **进入决定**：协调者产生实际决定，记录参与者及来源。
4. **登记行动任务**：把决定交给负责 Bot，进入正常任务执行和验收流程。
5. **结束会议**：保留会议记录。取消会议与停止已登记行动任务分开操作。

修改成员或议题会更换相应世代；旧意见和迟到输出不会混入新议题。缺席、失败、预算不足和未知状态分别记录，不冒充全员完成。

## 普通会话、归档与恢复

**管理 → 会话管理** 分页列出普通会话、Bot 联络、工作及群会议会话，包括归档和异常对象。已完成的回复会先保存，再读取对应原生分页，不必等待后台批量保存周期。**查看原生会话** 使用 DSH 本来的会话界面；列表本身不会唤醒全部 Agent。

普通会话和 Bot 联络会话正在回复时，可以使用 **停止当前回复**。工作执行使用任务卡片的 **停止本次尝试**。停止当前回复保留原生待处理队列；后续输入继续按 DSH 原生规则处理。

Bot 获得普通会话的控制授权后，可向已有冷会话发送消息或配置已结算会话，无需先在界面打开它。普通会话继续由 DSH 管理，停用插件不会取消它或撤销已经保存的名称、preset 和模型选择；重启并启用插件后，即使此前尚未发送消息，也会恢复已确认的回复参数。随后在原生界面选的新模型仍生效，插件配置不会修改全局默认模型。

投递在消息真正入队前检查最新来源权限。权限撤销而尚未入队的消息保留原始 ID；恢复权限后需明确接续。入队状态未知时先查原生日志和回执，不自动重复发送。

归档保存日志与身份；恢复回到同一对象。普通会话与 Bot 会话在归档／恢复的原生变更和回执落定期间都封住新的原生准入，最终结算检查不能被并发模型或工具工作绕过。会话正在保存配置时，归档／恢复会提示操作尚未完成，待配置回执落定后再操作。重查已完成的原始归档／恢复回执不改变会话当前状态。未知状态或坏日志需要查回原证据，界面不会建立替代对象假装恢复成功。

禁用、重新启用或卸载后重装插件，正常结算的 Bot 记忆和任务保留。重载会重新绑定仍由 DSH 管理的既有 Bot 联络会话，沿用原身份、模型约束与工具边界；无法确认的既有活动仍须查回，不释放未知资源。升级步骤见 [安装说明](install.zh-CN.md)。


## 记忆与资料

在 **记忆** 中选择 Bot，可搜索、按类别筛选、编辑及固定重要记忆。每 Bot 最多固定 8 条；固定操作也检查保存后完整记忆记录的字节额度，超额时不写入。编辑会检查开始时的版本，保留原来源、遗忘与保护标记。自动上下文带入有界的完整记忆摘要和未完成任务；正文细节按需查询。

“资料”支持粘贴正文、UTF-8 `.txt`／`.md` 文件，以及指定原生日志的文本范围。每份正文最多 64 KiB，不改写原文；修订创建新资料身份。中文检索返回精确原文块、行号和引用，打开时重新检查来源权限。资料中的 HTML 或指令不会由插件执行；PDF／Office 先通过已有 DSH 工具提取正文。

选择文件后会显示读取进度，读完再编辑标题、正文和保存；连续选择时使用最后选择的文件。未编辑的上传正文保留原始 UTF-8 内容及换行。切换 Bot 或离开当前记忆页面后，旧搜索结果不会覆盖新的列表。资料搜索始终以最后一次查询为准；重试成功会清除该次搜索错误，保留后来其他操作的错误；点击“显示全部资料”后，旧搜索不能再恢复筛选。迟到的读取错误不会出现在已经离开的页面。

“导入导出”只处理所选 Bot 的长期记忆 JSON。导入先预览重复、来源可验证状态及固定额度，确认后按原文件 SHA256 和目标记忆版本原子追加。文件最多 500 条、4 MiB；不复制凭据、共享、授权或运行态。外部环境的保护来源无法验证时保存为不可用，不进入 Bot 上下文；不会把同名外部 ID 当成本地来源。

重新导入本地导出过的记忆时，会核对原记忆、导入回执及原始来源；再次导出／导入保留可验证归属而不反复嵌套历史。多来源及历史引用除文件限额外，还须通过格式检查并能由官方原生存储完整编码。合法 JSON 也可能嵌套过深，超过原生编码能力时预览或确认会明确拒绝，说明未写入；不会截断来源或留下部分导入。确认导入时重新检查最新记忆、资料和授权：预览后实际来源被编辑、遗忘、变得不可用或权限撤销，不会继续使用旧预览将其视为可用记忆。

更换导入文件后，旧预览的确认立即失效；取消、切换 Bot 或离开页面后，旧文件读取及预览回复不会重新打开确认。再次导入需重新选择文件并核对新预览。

## 模板、依赖和责任交接

在 Bots 或协作页选择个人助理、资料整理、开发、测试配方；团队模板一次创建完整角色与内部群。模型从当前 DSH 目录选择，任一角色无效则整队不创建，也不立即启动模型。

任务卡可以设置前置任务（最多 30 项），禁止环。前置条件必须是当前定义下、确切尝试真实结算后明确记录的“验收通过”；只返回结果不能解锁。阻塞任务不占槽，不自动级联开始。已经开始的尝试保存当时的固定输入，后续上游变化不改写它。

交接只在任务、子工作、父尝试和相关投递真实结算后进行。接收 Bot 必须可控制且有权读取必要来源。交接保留任务 ID、定义、旧尝试、原日志和验收，新负责人下次明确开始才执行。未知工作先查回；停止接受回执不能替代结算。

## 简报、提醒与定时

Bot 联络会话的身份旁可打开任务简报和未读结果。摘要来自已保存的真实结果，每项最多 800 个字符，不额外调用模型。确认已读只针对该通知，不清除更新尝试的结果，不改变验收或停止任务。

在任务页展开“提醒与定时”，选择负责 Bot、时区和单次／固定间隔／每日／每周规则。创建后负责人固定，编辑已有安排时会显示该 Bot，不能更换；需要另一负责人时另建安排。默认时区为北京时间；固定间隔至少 15 分钟。提醒只产生插件通知；定时任务按确认配方创建独立任务与尝试，遵守容量、依赖和原生审批。

DSH 关闭时不运行。任务错过周期默认跳过并提醒；明确选择“恢复后补最近一次”只补最近一次，保留原触发身份，并使用固定的 60 秒恢复准入窗口。暂停／重启不会延长窗口；UNKNOWN 不自动重放。每个定时配方最多一个未结算工作，每 profile 最多 100 个未归档配方和 10000 条触发记录。历史满时可明确清理已结算／错过且无待查回引用的记录，原任务和回执保留。

修改 Bot 执行配置或失去接收位置／来源权限时，定时暂停，需明确更新配方重新确认。暂停或取消定时阻止新准入；原在途任务仍按原尝试和触发 ID 结算，不必重新启用安排。停止已在途工作使用其真实任务停止操作。

重新确认后，能证明尚未开始执行的旧触发保留为错过记录，新规则从新触发开始；原任务和操作回执保留。已准入或未知工作仍需按原身份结算，重新确认不会绕过它们。

修改未来配方不会改写已经准入任务的原配方、尝试和回执；其原结果继续按原接受证据投递，同时重新检查当前 Bot 状态、接收会话、来源及跨 Bot 授权。新任务只使用最新确认的规则。先在禁用状态重新确认、随后启用时，也会将确证尚未准入的旧触发保留为错过，允许未来周期继续；未知或已有准入证据的旧触发不能按此方式清除。

## 本地诊断

在管理页打开诊断预览并复制，内容仅含版本、平台、功能状态、对象数量和明确选择的原操作 ID。更换所选原操作或关闭预览后，迟到回复不能恢复旧预览或复制入口。预览与复制一致，不包含正文、模型密钥、绝对路径、鉴权链接或原始异常，不自动上传。
