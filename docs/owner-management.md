# Owner control sessions

`dsh-bot/host` exports `Host.openOwnedControlSession(caller, options)`. A trusted launcher that already retains the exact Host owner capability supplies `options.envelope`, `options.payload: {controlSessionId}` and an optional synchronous `isCurrent(): boolean`. A UUID controlSessionId is ordinary identity, not an authentication credential. Public Cordis/operator/browser services remain read-only and cannot acquire this port from serialized actor labels or copied IDs.

Open uses command `openControlSession`, this Host's `ledgerInstanceId`, `authorizationRef: 'native-owner'`, `expectedRevision: null`, and `expectedEpochs.nativeOwner` equal to the existing grant epoch. The frozen returned port has only controlSessionId, selectExistingBot, createBot, query and dispose. Each method takes the existing full CommandEnvelope and a digest-bound payload containing that same controlSessionId. Commands are respectively `selectExistingBot`, `createBot`, `queryControlSession`, and `disposeControlSession`. New operations bind expectedRevision to the control revision and expectedEpochs.control/nativeOwner to its epoch and retained grant epoch. Existing operation/nonce collisions are rejected.

Selection takes `{controlSessionId, botId, expectedBotRevision}` and `expectedEpochs.bot`, captures an already-existing active same-owner Bot, and never creates another Bot. Creation takes `{controlSessionId, name, config}` using existing contact/execution model routes, agentPreset, sessionModes and autonomy rules. It creates one registered Bot through the existing Host handler, captures its immutable config version, and selects it. Returned change receipts include the updated control revision/epoch/memberCount/selectedBotId and exact safe Bot/config reference.

Query takes `{controlSessionId, botIds, taskIds}` and an expected epoch under `expectedEpochs['bot:' + botId]` for every requested Bot. Bot/task lists each allow at most 500 distinct IDs per request; request exact batches from any-sized membership. All Bot IDs must be members and all task IDs must belong to those requested Bots. Returned Bot DTOs include configVersion and only provider/model/reasoning routes plus agentPreset; task DTOs retain the established safe read projection. Missing or foreign IDs refuse the entire query. Query is a synchronous short ledger operation; it does not invoke native execution.

The captured reference uses existing immutable configVersion and opaque agentPreset semantics. Healthy built-in and custom compositions are opaque IDs; catalog names do not classify runtime types. A null or legacy missing agentPreset preserves existing healthy-default resolution when a future Session is explicitly created. Plan/permission sessionModes are separate. No executionMode or native/custom runtime enum, immutable preset-composition fingerprint, mode fallback or native execution is added.

A legacy explicit config update may create another version. Query refuses a changed captured configVersion or Bot epoch before cached replay. Explicitly select the same Bot with its current revision/epoch to recapture its new reference; then use a fresh current-revision query. Old config rows and operation receipts remain unchanged. Cached create/select receipts reuse their original IDs without another mutation; queries replay only while the control revision and target references remain current.

Management handlers also reject direct Host.execute/executeOwned or commands-map calls without the exact private retained-port dispatch context. Every cached receipt requires current owner lifetime and captured active grant epoch. A false/throwing/asynchronous lifetime callback or changed/revoked grant permanently fences that port; restoring the callback or grant cannot revive it. Async callbacks are denied synchronously and rejected Promises are handled. Wrong-Host, wrong-owner, stale epoch, bad digest/revision, expired request and disposed state fail closed.

Dispose advances only control state/revision/epoch and is terminal, including repeated disposal. Bots, tasks, config, conversations and native state remain unchanged. Another Host instance cannot adopt a retained control identity even with the same ledger, owner and caller; it must open a fresh ID. Retained control records do not implement session recovery.

The existing private `OwnedNativeController.controlPort(caller, options)` binds this projection to its exact Cordis fiber and closed/closing lifecycle. Stock rc.2 still lacks the development-only native dependencies, so that entry remains blocked in stock. Host management is available from its existing stock-importable package route; no native execution, archive/restore, background result/stop, GUI or production authentication claim follows.
